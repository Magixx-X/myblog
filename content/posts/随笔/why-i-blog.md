## 一个不太好回答的问题

"现在谁还看博客啊？"

这问题我被问过几次。坦率地说，从流量角度看，答案是否定的——一篇技术博客的阅读量，可能不如一条蹭对热点的微博。

但如果用"被看见"来衡量写作的价值，那这个标准从一开始就选错了。

## 写作是思考的显影液

有一类认识只有在动笔之后才会出现。

你觉得自己搞懂了某个东西，直到你要向别人解释它。这时候你会发现：

- 那个"显然"的步骤其实跳过了两个前提
- 那个"简单"的结论在一个边界条件下不成立
- 你一直用的那个术语，其实自己也没完全定义清楚

这些漏洞在脑子里是看不见的。**写下来才显影。**

我在写[上一篇关于 Git 工作流的文章](/posts/git-based-blog)时就有这个体验。我本来觉得"用 Git 管博客内容"这句话已经说明了全部，写的过程中才发现：文件命名和时间排序之间有个冲突，我从来没认真处理过。写完那篇才想清楚解决方案。

如果只是日常使用，这个漏洞可以一直藏着——它不影响我用。但写文章强迫我把它挖出来。

## 公开写作的额外约束

不公开的笔记也有这个作用，但强度低一档。

公开会加三个约束：

**一是准确性的自我审查。** 私人笔记里写错一个 API 名字，无所谓。公开文章里写错，会有人指出来（或者更糟，有人照着做然后失败）。这个压力迫使你去查证，而查证的过程本身就在修正认知。

**二是结构的强制。** 私人笔记可以是碎片、可以是想到哪写到哪。公开文章必须有一条能读下去的线。组织这条线的过程，就是把零散想法焊接成体系的过程。

**三是对读者的想象。** 你得假设读者不知道你的上下文——这个假设逼你把隐含前提写出来，而**隐含前提往往正是理解的关键**。

## 关于长文本

短视频和短文把信息密度推向了另一个方向：**单位时间的信息量最大化**。

但这有个代价。高度压缩的表达依赖大量共识——梗、缩写、心照不宣的立场。它传递的是"结论的碎片"，而不是"得出结论的过程"。

而过程的缺失是有后果的。看多了碎片，人会习惯直接接受结论，对"这个结论怎么来的"失去兴趣。发表观点越来越快，支撑观点的东西越来越少。

长文的价值恰好在这里：它**慢**。它要求你跟着走一遍推理。它允许"这个我不确定"这种表达存在。它在结论之外保留了条件、例外和权衡。

我不认为短内容应该被否定——它有它擅长的事。但两者不能互相替代：**短内容擅长传播，长文擅长沉淀。**

## 给自己写

还有个更个人的理由：**我经常回看自己写的东西**。

不是自恋。是因为半年后、一年后，我会忘记当时为什么做了某个决定。文章的正文里留着那些原因——当时的约束是什么，考虑过哪些方案，为什么否掉了它们。

这些东西在代码注释里放不下，在 commit message 里也放不下。它们需要一个不被打断的地方。

从这个角度看，博客的第一读者是我自己。访问量是副产品。

## 那还发出来干嘛

既然主要是给自己写，为什么不放在本地？

因为公开这个动作会**提高标准**。

知道可能会有人读到，你会多检查一遍；会多花时间把话说清楚；会在写下绝对判断之前犹豫一下。这些犹豫和检查，最终都变成了文章质量的一部分。

而且偶尔——不是经常，但会偶尔——有人留言说"这个帮到我了"。这个反馈不构成写博客的理由，但它是个不错的奖励。

## 短版

写博客不赚钱，不涨粉，不高效。

但它是我知道的最便宜的、能强迫自己把一件事想清楚的方式。而且十年后回头看，它是唯一能告诉我"当年我在想什么"的东西。

流量会过去。写下来的东西不会。

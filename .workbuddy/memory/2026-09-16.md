## 排错：浏览器能开 GitHub，终端 git 推送失败

用户反馈「浏览器可以打开网页，但终端上传失败（已开代理）」。

**根因：Git 不读 Windows 系统代理。**

浏览器走的是代理软件写进系统（WinINET）的代理设置；Git 用的是自己的 libcurl，
只认 `http.proxy` / `https.proxy` 配置项或 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。
用户全局配置里只有 `credential.helper=manager`，没有任何 proxy 项 → git 直连 `github.com:443`
→ 21 秒后超时。

**实测对比（同一台机、同一个 URL）：**

| 方式 | 命令行 | 结果 |
|---|---|---|
| 直连（git 默认） | 不设代理 | `Failed to connect to github.com:443 after 21126 ms`，exit **128** |
| 走本机代理 | `-c http.proxy=http://127.0.0.1:7897` | 无报错，exit **0** |

**关键环境事实：**

- 用户本机代理软件端口是 **`127.0.0.1:7897`**（Clash Verge 默认混合端口，`netstat` 可见 LISTENING）。
- `127.0.0.1:53903` 是 **WorkBuddy 沙箱自己的出口代理**，只注入到 bash 工具的环境里，
  和用户的代理软件无关 —— 别把两者搞混，之前「push 被 502 拦住」就是它。
- `netsh winhttp show proxy` → 「直接访问(没有代理服务器)」；WinINET 注册表项因
  `reg.exe` 被沙箱黑名单拦截，读不到，只能靠 netstat 反推代理端口。

**给用户的解法**（按推荐顺序）：给 git 配代理 / 临时设环境变量 / 代理软件开 TUN 模式接管全局。

**顺带发现**：用户已自行把 remote 改成无 `.git` 后缀的 `https://github.com/Magixx-X/myblog`，
两种写法对 GitHub 等价。

**仍未做的**：仓库里跟踪了 `.workbuddy/memory/*.md`；`启动博客 - 副本.txt` 未跟踪。都待用户决定。

## 用户困惑：为什么这些改动没进那次提交

用户看 VS Code 左侧有「暂存的更改」/「更改」，问为什么没提交上去。三个原因叠加：

1. **commit 只收录"暂存区"在那一刻的快照**。`git add -A` 是在这些笔记写出来**之前**跑的，
   之后对文件的修改全部停在"工作区"，不会自动进入提交。
   证据：提交里 `2026-09-16.md` 是 35 行，而现在该文件还有 **+64 行**没提交（`git diff --cached --stat`）。
2. **`启动博客 - 副本.txt` 上轮被主动移出了暂存区**（重复文件），自然不在提交里；这次它又被重新 add 成 `new file`。
3. **commit ≠ push**。即使提交了，不 push 也不会出现在 GitHub 上。

## 排错：「VS Code 上传没反应」

用户报 VS Code 点上传无任何反应。**根因是操作顺序漏了一步，不是网络故障。**

**决定性证据**：`git rev-list --count origin/main..main` = **0**，本地 HEAD 与 origin/main 都是 `a98505a`。
**没有任何已提交的内容可推** → `git push` 是空操作，VS Code 的「推送/同步更改」自然毫无反应。

那 2 个文件（`.workbuddy/memory/*.md`）当时躺在**「暂存的更改」**里 ——
**add 了但没 commit**，不属于任何提交，push 不会带上它们。
VS Code 里的正确顺序是：**暂存 → 写信息 + 提交(✓) → 推送**，用户跳过了中间那步。

**其他查证结果：**

- 代理配置正确且**隧道通**：`~/.gitconfig` 里 `[http "https://github.com"] proxy = http://127.0.0.1:7897`。
  禁用凭据助手后 `ls-remote` 返回 `could not read Username for 'https://github.com'` →
  **说明请求已到达 GitHub 并拿到 401**，代理没问题，只是缺认证。
- **仓库是私有的**（匿名访问要登录）。这是新信息。
- **凭据已缓存在 GCM**（`credential.helper` 指向 PortableGit 自带的 `git-credential-manager.exe`），
  所以 01:17 那次 `ls-remote` 能不带交互直接成功。
- **`git push` 在沙箱里会挂死**（`--dry-run` 也一样，SIGTERM 收场）：
  无法弹出凭据窗口 / GCM 走交互流程时在这里会一直等。**别再试**。
  但 `ls-remote` 这类只读操作能跑通，可以用来判断远端状态。
- VS Code 用的是 PortableGit（PATH 里只有它，系统无 Git for Windows）。

**副产品**：用户已删掉 `启动博客 - 副本.txt`，并把它从暂存区撤出，工作区一度干净。

**给用户的正确姿势（记住这三条）：**
1. `git add` 之后又改了文件 → **必须再 add 一次**

# 2026-09-15

## 从零搭建个人博客站（我的博客）

**需求**：文章列表、文章详情、标签分类、关于页面、Markdown 渲染。前端 Vue，后端内容用 Markdown + Git 维护（无数据库、无 CMS）。

### 技术选型（已定）

- Vue 3 + `<script setup>` / Vite 5 / vue-router 4（History 模式）
- markdown-it + markdown-it-anchor 渲染正文
- highlight.js **按需注册语言**（`highlight.js/lib/core` + 逐语言 import），全量引入 1.3MB → 327KB
- **自研 front-matter 解析器**（`src/content/frontmatter.js`）—— 不能用 gray-matter，原因见下方坑 4
- 内容走 `import.meta.glob('../../content/posts/**/*.md', { query: '?raw', import: 'default', eager: true })`，构建期内联

### 核心设计决策

- **目录即分类**：`content/posts/<分类>/*.md`，分类从路径推导，不写进 front-matter。标签（多值）才留在 front-matter。
- **front-matter 字段**：`title` / `date` / `category` / `tags` / `summary` / `cover` / `pinned` / `draft`
- **草稿机制**：`draft: true` 在解析阶段直接过滤，不出现在任何列表/搜索/归档
- **渲染惰性缓存**：`post._html` 首次访问才渲染，列表页不渲染正文
- **搜索**：纯前端加权打分（标题 10 / 标签 6 / 摘要 4 / 正文 1），关键词存 URL `?q=` 可分享
- 主题切换用 CSS 变量 + `html[data-theme]`，默认跟随 `prefers-color-scheme`

### 踩过的坑（重要）

1. **gray-matter 把裸 `date: 2026-09-05` 解析成 JS Date 对象**，直接 `String()` 得到 `"Sat Sep 05 2026 08:00:00 GMT+0800"`，用它做 `localeCompare` 排序会完全错乱（Git 那篇 08-28 排到了 06-30 后面）。
   → 解法：`normalizeDate()` 统一产出 `YYYY-MM-DD` 字符串，**取 UTC 字段**（YAML 裸日期按 UTC 解析，用本地取值会跨时区偏移一天），并优先从原始字符串正则提取。

2. **front-matter 里未加引号的值包含冒号会炸 YAML**：`summary: 这篇设置了 draft: true，...` 直接抛 `YAMLException`，导致**整个构建失败**。
   → 解法：值里有 `:` 必须加引号；同时在 `posts` 的 map 里加了 try/catch，单篇解析失败只跳过并 console.error，不拖垮整站。

3. **Windows 下 glob 的 key 可能带反斜杠**，`rawFiles[post.path]` 查不到 → `matter(undefined)` 抛错 → 详情页白屏。
   → 解法：`getRaw()` 做规范化查表，三层兜底。

4. **⚠️ gray-matter 在浏览器里根本跑不了（最严重的一个坑）**。
   它内部依赖 Node 的 `Buffer` 检测 BOM/编码，而本站正文是构建期用 `?raw` 内联、**在浏览器里解析**的。
   浏览器没有 `Buffer`，于是每个文件都抛 `Buffer is not defined` 被 try/catch 吞掉跳过。
   **症状极具迷惑性：`npm run build` 成功、页面不报错、控制台一片安静，但一篇文章都不显示**（只有 header/footer 渲染出来）。
   —— 因为失败是运行时的 `console.error`，不是构建期错误，光看构建输出完全发现不了。
   → 解法：自研 `src/content/frontmatter.js`，只实现博客用到的 YAML 子集（标量 / ISO 日期 / 行内数组 / 块状数组），
   零 Node 依赖。同时从 package.json 移除 gray-matter。
   **教训**：验证必须真的在浏览器里渲染一遍，且要断言"文章卡片数量 > 0"，只看构建成功会漏掉整类故障。

## 追加：修复「npm run dev 打不开」+ 做启动脚本

**用户反馈**：`npm run dev` 打不开。

**真因**：5173 和 5174 被之前遗留的 vite 孤儿进程占着，
vite 静默退到 **5175**，用户按 5173 打开看到的是旧页面/空白。
注意 vite 的行为是「自动换端口 + 只提示一行」，很容易被忽略。

### 产出

```
scripts/start-dev.mjs      启动器（npm run dev / npm start）
scripts/port-utils.mjs     端口探测 + 进程树清理
scripts/free-port.mjs      手动释放端口（npm run free-port）
scripts/start-dev.sh       POSIX 薄封装（只找 node 后转交）
启动博客.bat                Windows 双击入口（薄封装）
scripts/test-port-utils.mjs  端口逻辑单测（17 项）
scripts/test-launcher.mjs    启动器端到端测试（14 项）
```

`npm run dev` 现在做的事：检查依赖 → 释放端口 → `--strictPort` 起 vite → 开浏览器
→ 退出时按进程树清理。端口腾不出来时**明确报错**，不再静默换端口。

### 关键技术结论（这几条很容易再踩）

1. **`netstat` 在 Windows 上不可靠，别用它判定「端口是否被占」**。
   实测 vite 明明在服务（curl 200），`netstat -ano [-p TCP|TCPv6]` 却什么都查不到
   （进程挂独立会话时尤其明显）。**改用 TCP 连接探测**（`net.connect` 到 127.0.0.1 和 ::1）
   判定占用——能不能连上比 netstat 说了什么更接近事实。
   netstat 只保留一个用途：确认被占之后尽力查出 PID 好提示/清理。

2. **必须按进程树杀，不能只杀直接子进程**。
   进程链是 `node(launcher) → cmd.exe → npx → vite → esbuild`（因为 `shell: true`）。
   只杀父进程 → vite 继续占端口 → 就是「停止后下次打不开」的成因。
   Windows 用 `taskkill /PID x /T /F`（`/T` = 连子树）。

3. **Windows 上 `child.kill('SIGTERM')` 等于强制终止**，
   Node 的 `SIGTERM` 处理器**不会触发**（`SIGINT`/`SIGKILL` 同理）。
   所以「信号转发保证干净退出」在 Windows 上不成立——任务管理器结束进程、
   直接关终端窗口，都会留孤儿。

4. **结论：自愈 > 完美清理。**
   既然退出路径无法保证，就把保障放在**启动时**：启动前清掉端口上的一切。
   端到端测试专门验证了这条链路：
   孤儿 270280 → 接管 265328 → 强杀后残留 265328 → 自愈 286288。

5. **vite 退出码 130/143/137 是正常停止**（Ctrl+C / SIGTERM / SIGKILL），
   不是错误。一开始我把它们当异常报红字，体验很吓人，已修。

### 测试写作教训

- **不能用「服务可访问」断言启动脚本成功**：孤儿/残留进程本身就在响应同一端口，
  会把它们的服务误判成新进程的成果。必须比较**端口占用者的 PID 是否更换**。
  第一版测试就因为这个假阳性通过了，掩盖了真实问题。
- 需要 `--open` 时注意：自动化测试里会弹用户浏览器，属预期行为。

### 验证结果

- 端口逻辑单测 **17/17**（含 `:5173` 不误中 `:51737` 的回归）
- 启动器端到端 **14/14**（孤儿接管 + 强杀自愈 + 站点渲染 + 清理）
- 冒烟测试 **35/35**（对 dev server 复跑）
- `npm run dev` 实测：正确占 5173，返回 200，标题「我的博客」

## 追加：启动器收尾修补

**背景**：工具侧的后台 dev server 被会话回收，退出码 1，脚本报「✗ vite 异常退出」
——这句把「进程被外部结束」误判成 vite 自身故障，会误导排查方向。

### 改动

1. **退出提示改中性**：非正常退出码不再说「异常」，改为
   「▸ vite 退出（code N）+ 若不是你主动停止，通常是终端被关闭或进程被外部结束」
   并引导往上翻看 vite 自己的报错。黄色而非红色。
2. **补 `PORT` 合法性校验**（真 bug）：`PORT=99999` 之前会一路传到 `net.connect`，
   抛 `ERR_SOCKET_BAD_PORT` 并甩出一串 Node 内部堆栈。现在启动时拦下并给友好提示。
   `free-port.mjs` 同步加了非法入参过滤。
3. **新增 `NO_OPEN=1`**：跳过 `--open`。
   起因是发现**启动器测试每次都会弹用户浏览器**（测试里 spawn 的就是 `start-dev.mjs`），
   `test-launcher.mjs` 的两处 spawn 已带上该变量。
4. README 补「其他启动选项」小节。

### 验证

- `PORT=99999` → 友好提示，无堆栈
- `free-port.mjs 99999 abc` → 提示忽略非法端口
- 杀 vite 进程触发非正常退出 → 提示中性、端口被清干净（6/6 临时断言，已删脚本）
- 完整测试套件重跑：**17/17 + 14/14**，冒烟 **35/35**

### bash 下的一个坑

`taskkill //F //PID x` 在 Git Bash 里**不会**被 MSYS 转成 `/F`，会报
「无效参数/选项 - '//F'」。要在 bash 里杀进程请用 `killPid()`（Node 直接调 taskkill，
不经过 shell 转义），或 `powershell Stop-Process`。
